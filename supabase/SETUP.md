# חיבור מסד הנתונים — פעם אחת, בערך 10 דקות

אחרי השלבים האלה בעל העסק מנהל מנות, מחירים וזמינות בעצמו, בלי לגעת בקוד.

---

## 1. יצירת הפרויקט

1. להיכנס ל-https://supabase.com ולהירשם (חינם)
2. **New project**
3. שם: `sisi-oven` · אזור: **Frankfurt** או **London** (הכי קרוב לישראל)
4. לבחור סיסמה למסד הנתונים ו**לשמור אותה במקום בטוח** — היא לא מופיעה שוב
5. להמתין כדקה עד שהפרויקט עולה

## 2. יצירת הטבלאות

1. בתפריט הצד: **SQL Editor** ‹ **New query**
2. לפתוח את הקובץ `supabase/schema.sql` מהפרויקט, להעתיק את **כל** התוכן ולהדביק
3. **Run**

זה יוצר את הטבלאות, את כללי ההרשאות, ומזין את 40 המנות שכבר באתר.

## 3. חיבור האתר

1. **Settings** ‹ **API**
2. להעתיק שני ערכים:
   - **Project URL** — נראה כמו `https://abcdefgh.supabase.co`
   - **anon public** — מפתח ארוך
3. לפתוח את `assets/db-config.js` ולמלא:

```js
window.SISI_DB = {
  url: 'https://abcdefgh.supabase.co',
  anonKey: 'eyJhbGciOi...'
};
```

4. לשמור ולדחוף ל-GitHub. Vercel מפרסם מחדש תוך דקה.

> **שני הערכים האלה אמורים להיות גלויים בדפדפן.** זה לא פרצה. ה-anon key לא
> נותן שום דבר מעבר למה שכללי ההרשאות ב-`schema.sql` מתירים: קריאת התפריט, וזהו.
> המפתח שהוא כן סוד נקרא **service_role** — אסור לשים אותו בקוד, בריפו או בכל
> מקום שמגיע לדפדפן.

## 4. יצירת המשתמש הראשון

1. **Authentication** ‹ **Users** ‹ **Add user** ‹ **Create new user**
2. להזין אימייל וסיסמה חזקה, ולסמן **Auto Confirm User**
3. להעתיק את ה-**User UID** שנוצר
4. לחזור ל-**SQL Editor** ולהריץ, עם ה-UID האמיתי:

```sql
insert into public.staff (id, role, display_name)
values ('הדביקו-כאן-את-ה-UID', 'admin', 'השם שלך');
```

**בלי השורה הזו אי אפשר להיכנס לפאנל** — וזו בדיוק הכוונה. משתמש שנרשם לבדו
ולא נמצא בטבלת `staff` נדחה.

## 5. בדיקה

להיכנס ל-`https://הכתובת-שלך/admin.html`, להתחבר, ולשנות זמינות של מנה אחת.
לפתוח את האתר הראשי — המנה אמורה להופיע כ"אזל מהמלאי".

---

## הוספת עובד נוסף

אותו תהליך כמו שלב 4, אבל עם `'staff'` במקום `'admin'`:

| | מנות וזמינות | קטגוריות | הגדרות העסק | הוספת משתמשים |
| --- | --- | --- | --- | --- |
| **admin** | ✓ | ✓ | ✓ | ✓ |
| **staff** | ✓ | ✓ | ✗ | ✗ |

ההבדל נאכף במסד הנתונים, לא בממשק. עובד שינסה לשנות הגדרות יקבל סירוב מהשרת
גם אם יעקוף את הכפתורים.

## אם משהו לא עובד

| מה רואים | מה הסיבה |
| --- | --- |
| "המערכת לא חוברה למסד הנתונים" | `db-config.js` ריק או לא נדחף |
| "המשתמש הזה אינו מורשה" | שלב 4 לא בוצע, או ה-UID שגוי |
| "אימייל או סיסמה שגויים" | בדקו שסימנתם Auto Confirm User |
| התפריט באתר לא השתנה | רענון קשיח (Ctrl+F5) — יש Service Worker שמטמין |
| שגיאת CSP בקונסול | הכתובת ב-`db-config.js` אינה `*.supabase.co` |
